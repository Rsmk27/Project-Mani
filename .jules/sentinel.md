## 2025-05-21 - [API Crash & Info Disclosure via Unsanitized Input]
**Vulnerability:** The `/api/chat` endpoint crashed (DoS) when an object was passed as the `query` field, resulting in `TypeError: query.trim is not a function`, and exposed the full stack trace. The `history` field was also prone to Prompt Injection, where users could overwrite system instructions by mimicking the "system" role in history elements.
**Learning:** Even internal-facing APIs must assume external inputs are completely untrusted. Using duck typing without explicit type assertions allowed crashes, and blindly trusting the role mapping passed by the client allowed prompt injections to succeed. Express doesn't automatically shield errors when the app crashes in specific parts of the request pipeline.
**Prevention:** Explicitly validate types for all API inputs (`typeof query === 'string'`, `Array.isArray(history)`). Forcefully map history roles to allow only 'user' or 'assistant'. Return a generic 500 error instead of exposing `err.message` from third-party services.
